## Intent

**Problem:** Гость выбирает блюдо в карточке, но не может собрать заказ из нескольких позиций.

**Approach:** Модуль `ordering` хранит серверную корзину гостя на точке: только выбор (блюдо, размер, модификаторы, количество), цена и доступность пересчитываются `catalog.api` при каждом чтении. В карточке блюда — «Добавить · N ₽», на меню — полоса «Корзина · N ₽», экран корзины меняет количество и удаляет позиции (FR-6, AD-6).

## Boundaries & Constraints

**Always:** корзина — одна на пару (пользователь, точка), видна с любого устройства; одинаковый выбор складывается в одну строку; добавить можно только полный и допустимый выбор; позиция, ставшая недоступной (стоп-лист, скрытие, удаление, нарушение правил группы), остаётся в корзине с пометкой «недоступна» и в сумму не входит; количество 1–99; имя блюда, размера и модификаторов сохраняется снимком для показа, если блюдо удалили.

**Never:** хранение цены в корзине; вычисление суммы на клиенте.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Добавить | Капучино 400 мл + сироп, 2 | строка корзины, сумма 56000 | — |
| Ещё раз то же | тот же выбор, 1 | одна строка, количество 3 | — |
| Другой выбор | то же блюдо, 250 мл | вторая строка | — |
| Неполный | крылышки без соуса | 422 `incomplete_selection` | — |
| Недопустимый | чужой модификатор | 422 `invalid_selection` | — |
| Изменить количество | `PATCH {quantity: 5}` / `0` | 5 / строка удалена | 1–99 |
| Стоп-лист | размер позиции выключен | `available: false`, `problem: unavailable`, в сумму не входит | — |
| Новая цена | персонал изменил цену | строка и сумма по новой цене | — |
| Удалённое блюдо | блюдо удалено | строка с прежним названием, `available: false` | — |
| Чужая строка | id строки другого гостя | 404 `cart_item_not_found` | — |

## Implementation Notes

- Решения принимает агент (поручение пользователя 2026-10-17). `catalog.api.quote` — цена с названиями, не бросает исключений: недоступный выбор даёт `problem`, удалённое блюдо — пустые названия (строка показывает снимок `title`).
- Строка корзины хранит id без внешних ключей: блюдо, удалённое из меню, остаётся в корзине «недоступным», а не исчезает молча. Модификаторы сортируются — одинаковый выбор складывается в одну строку.
- Корзина создаётся `INSERT … ON CONFLICT DO NOTHING` по паре (пользователь, точка).
- Mini App: `platform.showMainButton` (нативная MainButton Telegram; в браузере и dev-моке — липкая кнопка на странице через `MainAction`), контекст корзины, «Добавить · 280 ₽» в листе блюда, полоса «Корзина · N ₽», экран корзины с количеством и «Убрать» для недоступных.
- Найдено и исправлено попутно: `ruff --fix` удалял «неиспользуемые» импорты моделей из `migrations/env.py` и `conftest.py`, после чего autogenerate предлагал DROP всех таблиц. Регистрация моделей теперь — автопоиск `fenix.modules.*.models` через `importlib`; `alembic check` в CI ловит такое расхождение.
- Проверено в браузере: Капучино 400 мл + сироп → «Добавить · 280 ₽» → полоса «Корзина · 280 ₽» → экран корзины.
