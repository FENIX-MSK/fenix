# Epic 1 Context: Гость видит актуальное меню и информацию о кафе

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Гость запускает бота (обычным «Старт» или по QR-ссылке с меткой источника), открывает Mini App и видит всё меню «Феникс бистро» из печатного меню — категории, размеры, модификаторы, пометку «Закончилось» — и информацию о кафе со статусом «Открыто до…». Эпик закладывает фундамент всего продукта: модульный каркас бэкенда, аутентификацию Mini App, модель точки и каталога. Заказов, корзины и раздела персонала в эпике нет.

## Stories

- Story 1.1: Модульный каркас бэкенда и контракт API
- Story 1.2: Гость авторизуется в Mini App и запоминается с источником
- Story 1.3: Точка, часы работы и информация о кафе
- Story 1.4: Каталог и наполнение меню из PDF
- Story 1.5: Гость листает меню
- Story 1.6: Карточка блюда с размерами и модификаторами

## Requirements & Constraints

- Запуск бота без метки — источник `direct`; метка с первого запуска не перезаписывается.
- Статус «Открыто до HH:MM» / «Закрыто, откроемся в HH:MM» по часам работы в часовом поясе точки (по умолчанию `Europe/Moscow`), включая работу после полуночи и выходные.
- Меню: скрытые блюда/категории не показываются; блюдо, у которого все размеры в стоп-листе, — «Закончилось» и недоступно; цена «от N ₽» при нескольких размерах.
- Карточка блюда: правила мин./макс. выбора в группах модификаторов; недоступные опции неактивны; недопустимый выбор отклоняется сервером (`invalid_selection`).
- Главный экран ≤2 с на 4G; API меню ≤300 мс p95; экраны от 360 px, светлая и тёмная тема Telegram.
- Все запросы Mini App аутентифицируются подписью Telegram; без неё — 401 `unauthorized`.

## Technical Decisions

- **Модульный монолит.** Модули `identity`, `locations`, `catalog`, `ordering`, `payments`, `notifications`, `reporting` в `backend/src/fenix/modules/<m>/`; другой модуль импортируется только через `modules/<m>/api.py`. Платформенный код — `fenix/platform/`, роуты — `fenix/http/`, бот — `fenix/telegram/`. Нарушение границ ловит CI.
- **Владение данными.** Таблица принадлежит одному модулю, имя `<module>_<entity>` во множественном числе. `identity` — пользователи; `locations` — точки, часы, информация о кафе; `catalog` — категории, блюда, размеры, группы модификаторов, модификаторы, стоп-лист, фото.
- **API.** REST JSON под `/api/v1`; `/api/health` и `/metrics` — вне версии. Ошибки: `{"error": {"code", "message", "details"}}`. TS-клиент Mini App генерируется из OpenAPI в CI, ручных типов API нет.
- **Идентичность.** Пользователь = уникальная пара `(platform, external_id)`. Заголовок `Authorization: tma <initData>`, проверка HMAC от токена бота и `auth_date` ≤ 24 ч.
- **Цена.** Считает только сервер — `catalog.api.price(...)`; клиент цену не вычисляет. Деньги — целые копейки.
- **Данные точки.** `location_id` на всём, что относится к точке (стоп-лист, часы). Меню общее для сети.
- **Время.** В БД — `timestamptz` UTC; бизнес-время — в поясе точки.
- **Идентификаторы.** UUIDv7; логи structlog JSON без персональных данных.
- **Бот** — отдельный сервис в режиме polling через `TELEGRAM_PROXY_URL`; webhook не используется.

## UX & Interaction Patterns

- Токены DESIGN.md как CSS-переменные с переключением по `colorScheme` Telegram: светлая — фон `#F7EFE3`, акцент `#731419`; тёмная — фон `#2B0B0E`, акцент `#D4A96A`. Цвет шапки Telegram = фон.
- Заголовки, логотип «ФЕНИКС», категории — Tenor Sans заглавными с разрядкой; остальное — системный шрифт.
- Главный экран: шапка со статусом точки, баннер акции, прилипающая карусель категорий, карточки блюд (фото 72 px или заглушка с лучами), метка «Закончилось»; скелетоны при загрузке.
- Лист блюда: радио для «один из», чекбоксы с доплатой, итог с сервера (индикатор обновления вместо устаревшей цены), подсказка «Выберите …» при неполном выборе; закрытие — BackButton Telegram или свайп вниз.
- Обращение к гостю на «вы»; текст «Закончилось», «Сейчас мы закрыты. Откроемся завтра в 9:00.».

## Cross-Story Dependencies

- 1.1 — основа для всех историй: модули, `/api/v1`, формат ошибок, генерация клиента.
- 1.2 вводит пользователя и аутентификацию, на которые опираются все запросы 1.3–1.6.
- 1.4 создаёт таблицы каталога и стоп-листа, которые читают 1.5 и 1.6; 1.3 даёт точку (`location_id`) для стоп-листа.
- Корзина и кнопка «Добавить в корзину» — эпик 3; персонал и редактирование меню — эпик 2.
