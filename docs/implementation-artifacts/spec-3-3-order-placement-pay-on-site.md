## Intent

**Problem:** Гость собрал корзину и указал контакты — теперь нужен заказ с номером, который он назовёт на кассе.

**Approach:** `POST /api/v1/orders` в одной транзакции создаёт заказ со снимком позиций и цен, номер `#NNN` из атомарного счётчика точки на бизнес-день (часовой пояс точки), запись журнала и очищает корзину. Статус меняется только через `ordering.api.transition` по явной таблице переходов с compare-and-set по `version` (FR-12, AD-3, AD-6).

## Boundaries & Constraints

**Always:** цены в заказе — снимок на момент оформления; оплата на месте → статус `new`, онлайн → `pending_payment`; чужой заказ неотличим от несуществующего (404); отмена персоналом требует причины; из двух одновременных действий над заказом побеждает первое (409 второму).

**Never:** онлайн-оплата (3.5), уведомления (3.4, 3.6), доставка (эпик 5).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Оплата на месте | корзина, контакт, «наличными» | `#001`, `new`, `unpaid`, корзина пуста | — |
| Онлайн | «онлайн» | `pending_payment` | — |
| Пустая корзина | — | — | 422 `empty_cart` |
| Недоступная позиция | блюдо в стоп-листе | — | 422 `cart_has_unavailable` |
| Закрыто | вне часов | — | 422 `location_closed` |
| Нет контакта | без телефона/согласия | — | 422 `contact_required` |
| Конкурентность | 10 заказов одновременно | номера 1…10 без повторов | — |
| Новый день | следующий бизнес-день | номер снова `#001` | — |
| Переходы | вся таблица × все акторы | разрешено только перечисленное | 422 `transition_not_allowed` |
| Устаревшая версия | `expected_version` старый | — | 409 `order_conflict` |
