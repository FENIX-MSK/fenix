# Феникс бистро — опыт Mini App

Пометка `[ASSUMPTION]` — поведение, выведенное из PRD без прямого подтверждения заказчика.

## Foundation

- **Форм-фактор:** Telegram Mini App на телефоне (гость, сотрудник) и на планшете у кассы (сотрудник). MAX — позже, тот же опыт.
- **UI-система:** собственные компоненты на React по [DESIGN.md](DESIGN.md); платформенные элементы Telegram — MainButton, BackButton, вибрация, тема, «Поделиться контактом» — через слой `webapp/src/platform/`.
- **Одно приложение:** гостевая часть и раздел персонала; раздел персонала виден только сотрудникам.

## Voice and Tone

Обращение на «вы», тепло и коротко. Без восклицательных знаков в служебных сообщениях, без канцелярита.

| Ситуация | Текст |
| --- | --- |
| Приветствие в боте | «Добро пожаловать в «Феникс бистро»! Здесь можно посмотреть меню и заказать с собой или с доставкой.» |
| Заказ принят | «Заказ #047 принят. Будет готов к 9:20.» |
| Заказ готов | «Заказ #047 готов — ждём вас у кассы.» |
| Передан курьеру | «Заказ #047 уже едет к вам.» |
| Отмена | «К сожалению, заказ #047 отменён. Если вы оплатили онлайн, деньги вернутся.» |
| Закрыто | «Сейчас мы закрыты. Откроемся завтра в 9:00.» |
| Закончилось | «Закончилось» (на карточке), «Это блюдо закончилось — мы убрали его из корзины» (в корзине) |
| Ошибка сети | «Не получилось связаться с кафе. Проверьте интернет и попробуйте ещё раз.» |

Персоналу — так же на «вы», но короче: «Новый заказ #047 · самовывоз · 799 ₽».

## Component Patterns

- **Выбор в листе блюда:** «один из» — радио, первая доступная опция не выбирается автоматически, если группа обязательная; добавки — чекбоксы с доплатой справа («+30 ₽»); выбор сверх максимума не ставится, группа коротко вибрирует.
- **Итоговая цена** в листе блюда и корзине всегда приходит с сервера; пока ответ не пришёл, цена показывается с индикатором обновления, а не старым значением.
- **Основное действие экрана** — нативная MainButton Telegram («Добавить · 299 ₽», «Оформить · 799 ₽», «Оплатить», «Принять»); на экранах без MainButton — `primary-button` внизу.
- **Возврат назад** — нативная BackButton Telegram; лист блюда закрывается также свайпом вниз.
- **Метка «Закончилось»** — карточка приглушена и не нажимается; в листе блюда недоступные опции видны, но неактивны.
- **Статус заказа гостя** — горизонтальная лента шагов (Принят → Готовится → Готов → Выдан/Доставлен) с текущим шагом и временем.
- **Карточка заказа персонала** — одна главная кнопка следующего шага; второстепенные действия (отмена, изменить время, оплата) — в меню «…».
- **Отмена** — лист с причинами (Нет продуктов · Не успеваем · Адрес вне зоны · Гость попросил · Другое + поле), подтверждение вторым нажатием.

## State Patterns

| Состояние | Поведение |
| --- | --- |
| Загрузка меню | скелетоны карточек и чипсов; не больше 2 с до первой отрисовки (NFR-1) |
| Пустая категория | «Здесь пока пусто» с орнаментом |
| Пустая корзина | «В корзине пока ничего нет» и кнопка «В меню» |
| Нет заказов | «Вы ещё ничего не заказывали» |
| Кафе закрыто | меню доступно для просмотра, оформление заблокировано, плашка с часами работы |
| Приём приостановлен | как «закрыто», текст «Сейчас не принимаем заказы, скоро вернёмся» |
| Оплата не прошла | экран оплаты с «Попробовать ещё раз»; заказ ждёт оплату 15 минут, таймер виден |
| Нет связи | баннер сверху «Нет соединения», действия повторяются автоматически после восстановления |
| Конфликт у персонала | «Заказ уже изменил другой сотрудник» и обновлённая карточка (409) |
| Доска пустая | «Новых заказов нет» — спокойный экран, без анимаций |
| Оформление не заполнено | MainButton неактивна; под полем без телефона или согласия — подсказка, что нужно сделать |
| Слот стал недоступен | лист «Это время уже занято» с тремя ближайшими слотами |
| Загрузка фото | превью с прогрессом; при ошибке — «Не удалось загрузить фото» и «Повторить»; старое фото остаётся до успеха |
| Приглашение недействительно | бот: «Приглашение недействительно — попросите коллегу прислать новое» |
| Ошибка сохранения в редакторе | изменения остаются в форме, сообщение «Не сохранилось, попробуйте ещё раз» |

## Interaction Primitives

- **Вибрация:** лёгкая при добавлении в корзину и смене статуса, ошибка — при недопустимом выборе; на телефоне сотрудника новый заказ сопровождается вибрацией вместе со звуком.
- **Звук:** только на доске персонала — сигнал о новом заказе и о предзаказе, переходящем в работу; повторяется каждые 30 с, пока заказ не открыт или не принят `[ASSUMPTION]`. Включение звука — при первом входе на доску (ограничение браузеров).
- **Реальное время:** доска и экран заказа обновляются сами; новые карточки появляются сверху колонки с подсветкой на 5 с.
- **Прокрутка меню:** карусель категорий прилипает, выбранная категория меняется при прокрутке списка.
- **Подтверждения:** только для необратимых действий персонала (отмена заказа, отключение сотрудника).

## Accessibility Floor

- Контраст текста ≥4.5:1 в обеих темах (см. [DESIGN.md](DESIGN.md#colors)).
- Зоны нажатия ≥44 px; на планшетной доске кнопки действий ≥56 px `[ASSUMPTION]`.
- Состояние «Закончилось», статусы заказа и ошибки передаются текстом, а не только цветом.
- Все кнопки-иконки имеют подпись для экранного диктора.
- Анимации отключаются при системной настройке «уменьшить движение».
- Шрифт интерфейса — системный, масштабируется настройками телефона.
- Звук нового заказа всегда дублируется визуально (подсветка карточки) и вибрацией на телефоне; в фоне канал — сообщение в служебный чат.
- Итоговая цена и статус заказа объявляются экранным диктором при изменении (вежливая live-область).
- Таймер ожидания оплаты дублируется текстом «осталось N минут»; по истечении экран не закрывается молча, а показывает сообщение об отмене.
- Заголовки Tenor Sans капителью — не длиннее трёх слов в строке.

## Responsive & Platform

- 360–767 px: одна колонка; доска персонала — вкладки статусов.
- ≥768 px: доска — 4 колонки; гостевое меню — карточки в 2 колонки; лист блюда — модальное окно по центру.
- Тема: цвета берутся из DESIGN.md по `colorScheme` Telegram; цвет шапки и фона Telegram выставляется в `{colors.bg}` / `{colors.bg-dark}`.
- Полноэкранный режим Telegram не используется: приложение открывается в обычном режиме, чтобы был виден чат бота `[ASSUMPTION]`.

## Key Flows

Макеты экранов из этих сценариев: [mockups/key-screens.html](mockups/key-screens.html) — меню, лист блюда, оформление, заказ, доска персонала. При расхождении прав этот документ.

### Аня забирает завтрак без очереди (UJ-1)

1. Аня нажимает «Открыть меню» в боте — сразу видит «ФЕНИКС · Открыто до 22:00» и карточки.
2. Выбирает «Кофе» в карусели, открывает «Капучино», выбирает 400 мл и сироп — итог «280 ₽» на MainButton.
3. «Добавить · 280 ₽» — короткая вибрация, полоса «Корзина · 280 ₽» внизу. Добавляет сырники.
4. «Оформить» — самовывоз и «Как можно скорее (≈20 мин)» уже выбраны; телефон — одной кнопкой «Поделиться контактом», галочка согласия.
5. «Оплатить · 499 ₽» → успешно.
6. **Кульминация:** экран с крупным «#047» и лентой статуса; через минуту лента сама переходит на «Принят · готов к 9:20», и то же сообщение приходит в чат.
7. «Готов — ждём вас у кассы». Аня называет номер, получает кофе.

### Олег принимает заказ в час пик (UJ-5)

1. Планшет у кассы, открыта доска.
2. Звучит сигнал, в колонке «Новые» подсвечивается #047.
3. **Кульминация:** Олег нажимает «Принять» — время «9:20» предложено, он оставляет его; карточка уезжает в «Готовятся», у Ани в телефоне статус меняется.
4. Собрав заказ — «Готов»; при выдаче — «Выдан» (оплата онлайн уже отмечена).

### Миша получает скидку в день рождения (UJ-4)

1. На оформлении Миша отмечает «У меня день рождения» — онлайн-оплата скрывается с пояснением «Скидку подтвердим при выдаче — оплата на месте».
2. Итог показан как «≈ 899 ₽ со скидкой».
3. **Кульминация:** у кассы сотрудник видит метку «День рождения — проверить документ», подтверждает — итог фиксируется, Миша платит картой.

### Игорь заказывает ужин к 19:30 с доставкой (UJ-2)

1. В 17:00 Игорь собирает пиццу и сет, на оформлении переключает «Доставка».
2. Заполняет корпус и квартиру, подъезд и этаж — по желанию; в итоге видит доставку отдельной строкой.
3. В «Когда» выбирает слот 19:30 из списка на сегодня.
4. Оплата наличными, «Сдача с 5000».
5. **Кульминация:** экран заказа показывает «Запланирован на 19:30»; в 19:00 заказ уходит на кухню, в 19:35 приходит «Заказ #061 уже едет к вам».
6. Сбой: если адрес вне ЖК, сотрудник отменяет — Игорь получает сообщение об отмене без причины и может позвонить в кафе с экрана «О кафе».

### Аня повторяет заказ (UJ-3)

1. Аня открывает «Мои заказы», у прошлого заказа нажимает «Повторить».
2. **Кульминация:** корзина собрана за одно нажатие, итог по текущим ценам.
3. Сбой: если сырники закончились, над корзиной — «Сырники закончились — мы их не добавили».

### Олег ставит молоко в стоп-лист (UJ-6)

1. Персонал → «Стоп-лист», поиск «молоко».
2. **Кульминация:** переключатель «Альтернативное молоко» — выкл.; у гостей опция сразу неактивна.
3. Вечером переключатель обратно — опция снова доступна.

### Света добавляет новый бургер (UJ-7)

1. Персонал → «Меню» → «Бургеры» → «Добавить блюдо».
2. Название, состав, вес, цена; снимает фото телефоном — превью с прогрессом.
3. Привязывает группу «Котлета» (обязательный выбор) и «Добавки».
4. **Кульминация:** «Сохранить» — бургер появляется у гостей в категории.
5. Сбой: если связь пропала, форма сохраняет введённое и предлагает повторить.

### Владелец смотрит итоги недели (UJ-8)

1. Персонал → «Ещё» → «Отчёты», период «Неделя».
2. **Кульминация:** выручка, число заказов и средний чек сверху крупно; ниже — оплата, способы получения, топ блюд, отмены, источники гостей.
3. В «Кафе и настройки» меняет время приготовления на 25 минут — новое время сразу видно гостям в «Как можно скорее».

### Новый бариста получает доступ (UJ-9)

1. Света: «Ещё» → «Сотрудники» → «Пригласить» → «Отправить ссылку» в Telegram.
2. **Кульминация:** бариста открывает ссылку, бот отвечает «Готово, у вас есть доступ к разделу персонала», в шапке Mini App появляется «Персонал».
3. Сбой: ссылка старше суток — «Приглашение недействительно — попросите коллегу прислать новое».
