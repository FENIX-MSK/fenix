# Феникс бистро — зафиксированные решения

Черновик требований и архитектурных решений до старта разработки.
Станет входными данными для PRD и архитектуры (BMAD / SDD).

Обновлено: 2026-10-16 (после запуска стенда).

## Продукт

- Бот + Mini App для кафе «Феникс бистро» (фастфуд: роллы, сеты, пицца, бургеры, закуски, лепёшки, кофе, лимонады, напитки, десерты).
- Мессенджеры: сначала Telegram; MAX — позже (доступа пока нет), архитектура должна это позволять.
- Один бот, две роли: **клиент** и **сотрудник**. Все сотрудники имеют равные права.
- Точка сейчас одна; сущность «Точка» закладывается сразу под будущую сеть.
- Язык интерфейса — русский.
- Ожидаемая нагрузка — сотни заказов в день и больше.

## Клиент

- Меню, информация о кафе (адрес и карта, часы, телефон, соцсети, фото, акции).
- Корзина хранится на сервере; цену всегда считает сервер.
- Заказ: самовывоз (основной сценарий) и доставка.
- Предзаказ (опционально): только в пределах текущего дня, слоты с шагом 15 минут (настраивается).
- Время приготовления по умолчанию — 20 минут (настраивается); от него считается ближайший слот.
- История заказов и повтор заказа (с учётом стоп-листа и актуальных цен).
- Данные клиента берутся из Telegram (имя, телефон через «Поделиться контактом»).
- Обязательное согласие с политикой конфиденциальности перед первым заказом. Текст политики готовит заказчик.

## Оплата

- Способы: онлайн (пока мок за интерфейсом провайдера, позже реальный эквайринг), наличные, карта на кассе.
- Статус заказа и статус оплаты — раздельные поля.
- Онлайн-оплата: заказ попадает к персоналу только после оплаты; неоплаченный заказ автоматически отменяется по таймауту.

## Доставка

- Своя доставка по территории ЖК рядом с точкой. Интеграции с агрегаторами пока нет.
- Стоимость доставки фиксированная, задаёт оператор.
- Порога бесплатной доставки и минимальной суммы заказа нет.
- Адрес не валидируется автоматически — проверяет оператор.
- Поля адреса: дом/корпус, подъезд, этаж, квартира, комментарий, телефон; для наличных — «сдача с».

## Акции и скидки

- Сущность «Акция»: процент на всё меню или на категорию, даты действия, включается из админки.
- Акции двух типов:
  - **автоматические** — применяются в приложении сразу;
  - **с проверкой сотрудником** (например, скидка 10% в день рождения) — подтверждаются сотрудником в кафе; такой заказ оплачивается только на месте, онлайн-оплата и карта — без скидки (см. открытые вопросы).
- Промокоды и программа лояльности — позже.

## Меню

- Каталог: категория → товар → варианты (размер/объём со своей ценой) + группы модификаторов (min/max выбор, доплата), группы привязываются к товару или к категории.
- Сеты — обычные товары с описанием состава.
- Стоп-лист по вариантам и модификаторам, управляется сотрудниками.
- Фото блюд — в собственном S3-хранилище (Garage); загружаются сотрудниками через админку.
- Начальное наполнение — перенос всего меню из PDF в seed-данные (без фото).
- Скрытые служебные поля (себестоимость, артикулы) пока не нужны.

## Персонал

- Работа с личных телефонов и планшета.
- Доступ сотрудника — по одноразовой ссылке-приглашению.
- Одна служебная группа в Telegram для всех заказов (доставка помечается в карточке).
- Доска заказов в реальном времени со звуковым сигналом о новом заказе.
- Отмена заказа любым сотрудником; причина обязательна, клиент текст причины не видит.
- Номер заказа короткий, сбрасывается ежедневно: #001, #002…
- Отчёты для владельца (выручка, число заказов за период) — обязательно.
- Интеграция с кассой — отложена.

## Техника

- Бэкенд: Python 3.14 (3.13 не скачивался из-за сети; 3.14 — стабильная ветка), FastAPI, aiogram 3, SQLAlchemy 2 (async), Alembic, PostgreSQL, Redis, фоновый воркер; uv, ruff, mypy, pytest.
- Архитектура — модульный монолит; transactional outbox для уведомлений; идемпотентность платежей.
- Фронтенд Mini App: React + TypeScript + Vite, `@telegram-apps/sdk` за собственной обёрткой (под будущий MAX).
- Хранилище файлов: Garage (S3 API, AGPLv3). MinIO отказались: с конца 2025 он не публикует образы (Docker Hub и quay.io отказывают в pull), обновлений безопасности нет. Код работает через стандартный S3 API, поэтому переход на облачный S3 (Selectel, Yandex) — смена настроек. Замена MinIO → Garage — на этапе 1.
- Инфраструктура: VPS в РФ (Ubuntu 22.04, 2 vCPU / 4 GB), Docker Compose, Caddy с автоматическим HTTPS; временный домен — `fenix.kitexp.ru` (A-запись на VPS), запасной адрес `84-54-56-12.sslip.io`; сертификаты Let's Encrypt.
- Доступ к Telegram: с VPS IP Telegram заблокированы. Исходящие запросы бота идут через сервис `tg-egress` (туннель AmneziaWG до VPN-сервера в Амстердаме, только подсети Telegram, SOCKS5 внутри Docker). Конфиг туннеля хранится только на сервере.
- Бот работает отдельным сервисом в режиме polling (не webhook): входящие соединения от Telegram на VPS ненадёжны. База и персональные данные остаются на сервере в РФ (152-ФЗ).
- Нужен отдельный тестовый бот для локальной разработки, чтобы не перехватывать обновления у стенда.
- Фоновый воркер — собственный asyncio-процесс `fenix-worker`, без taskiq: отложенные действия и так лежат в БД (outbox, сроки заказов), воркер опрашивает их дважды в секунду — уведомления и доска укладываются в 5 с. taskiq удалён (отклонение от формулировки AD-13, суть AD-13 сохранена).
- Онлайн-оплата до v1 — тестовый провайдер: в Mini App экран «Оплатить / Отказ банка (тест)», деньги не списываются.
- Служебный чат привязывается командой `/bind` в группе; кнопка «Открыть заказ» в группе ведёт в личный чат бота (кнопки Mini App в группах Telegram запрещены).
- Мониторинг: Grafana (метрики + логи + алерты).
- Бэкапы — пока не делаем.
- Git: GitHub-организация FENIX-MSK. Ветки `develop` (интеграция, без деплоя) и `release` (CI/CD деплоит на VPS).
- Код, комментарии и коммиты — на английском; документация для заказчика — на русском.

## Репозиторий и процесс

- Монорепо https://github.com/FENIX-MSK/fenix (публичный — секреты только в `.env` и GitHub Secrets): `docs/`, `backend/`, `webapp/`, `infra/`.
- Методология: BMAD Method + spec-driven development; спецификации в `docs/` рядом с кодом.
- Фронтенд деплоится независимо (CI по путям); где хостить — решим позже.
- Скидка дня рождения: клиент отмечает её при заказе → онлайн-оплата недоступна → сотрудник проверяет документ при выдаче и подтверждает скидку (на месте — при любой оплате); без подтверждения — полная цена.
- Разработка локально; Mini App открывается через тестовое окружение Telegram (HTTP допустим).
